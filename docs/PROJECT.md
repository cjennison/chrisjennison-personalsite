# Christopher Jennison: Professional Profile Website

## Project Overview

A minimal, text-first professional profile for Christopher Jennison, Principal Software Engineer at Microsoft Copilot Studio. The site exists to help hiring managers, recruiters, and AI recruiting systems understand who Christopher is, what he has achieved, and how to reach him (LinkedIn only).

The site was rebuilt in October 2026 from a services/consulting portfolio into this profile. The services pages, case studies, contact form, and animated sections were removed.

## Goals

- **Scannable in seconds**: name, title, location, summary, and LinkedIn call to action appear above the fold.
- **Machine-readable**: all content is server-rendered HTML, backed by schema.org JSON-LD and a plain-text `/llms.txt`, so ATS parsers and LLM-based screeners extract accurate details.
- **Achievement-led**: an "Impact" section leads with quantified outcomes.
- **Consistent with LinkedIn**: titles, companies, and dates mirror the LinkedIn profile so automated cross-checks match.
- **Minimal**: one narrow column, one accent color, light/dark mode, no animations.

## Technology Stack

- **Framework**: Next.js 15 (App Router, Turbopack), React 19, TypeScript (strict)
- **UI**: Mantine 8 for components and color theming; Tailwind CSS 4 for layout utilities only
- **i18n**: next-intl 4 with English, French, and German (`/[locale]` prefix always present)
- **Analytics**: Vercel Analytics and Google Analytics 4 (page views, scroll depth, theme changes, resume prints)
- **Lint/format**: Biome (`npm run lint`, `npm run format`)

## Pages and Routes

| Route | Purpose |

| `/[locale]/resume/pdf` | One-page US Letter resume sheet (noindex). Source for the static PDFs |

### Home page sections (`src/app/[locale]/page.tsx`)

1. **Intro** (`ProfileIntro`): headshot, name (h1), headline, location, summary, "Strongest fit" roles, LinkedIn/resume/GitHub actions, a language notice on fr/de, and a personal note (daughter's age computed from `PROFILE.daughterBirthDate`; page revalidates daily).
2. **At a glance** (`AtAGlance`): four headline stats.
3. **Impact** (`ImpactList variant="full"`): four achievements with before → after or value metrics.
4. **Experience** (`ExperienceList variant="summary"`): companies and roles with dates and one-line summaries.
5. **Skills** (`SkillsList`) and **Education** (`EducationList`).
6. **Footer** (`SiteFooter`): LinkedIn as the only contact path.

### Resume page (`src/app/[locale]/resume/page.tsx`)

Header with contact URLs and a "Download PDF" button (links to the locale's static one-page PDF), then Summary, Impact (`variant="compact"`), Experience (`variant="detailed"` with location and highlights), Skills, and Education. Print CSS in `globals.css` renders black on white, hides site chrome, and keeps headings with their content.

### One-page PDF resume (`src/app/[locale]/resume/pdf/page.tsx`)

`OnePageResume` renders a US Letter sheet styled by the `.resume-sheet` rules in `globals.css`: fixed black on white (independent of the site theme), Calibri/Arial, and a named `@page resume-sheet` with zero margin. Its design follows ATS parser guidance from Greenhouse's resume-parsing docs and Jobscan:

- A single column with no tables, text boxes, images, or page header/footer regions. Contact details are in the body.
- Standard section headings (`Profile.onePage.headings`): Professional Summary, Key Achievements, Professional Experience, Skills, Education.
- Each role is one "Title, Company (Type) … Mon YYYY – Mon YYYY" line. Only roles in `ONE_PAGE_DETAILED_ROLE_IDS` get bullets; earlier roles are a single line each; roles in `ONE_PAGE_HIDDEN_ROLE_IDS` (the Code Upscale Strategic Advisor contract) are left off the PDFs to reduce overlapping-role noise.
- Plain words instead of symbols such as arrows or icons. The PDF title metadata comes from the page `<title>`.

Regenerate the PDFs after any content change: run the site (`npm run dev` or `npm start`), then run `npm run resume:pdf`. The script (`scripts/generate-resume-pdf.mjs`) drives an installed Edge (`RESUME_BROWSER_CHANNEL`, default `msedge`) via `playwright-core`, writes `public/*.pdf` using the file names in `RESUME_PDF_FILES`, and **fails if any PDF exceeds one page**. If that happens, tighten the `Profile.onePage` copy for that locale.

### Private role-tailored resumes (local only)

Role-specific one-page resumes are generated from gitignored files so tailoring and contact details never reach the public site or this public repo:

- **Content:** `private/resumes/variants/<id>.json` (gitignored) holds a `ResumeVariant` (see `src/lib/resume-variants.ts`): `targetTitle`, `fileName`, `headline`, `summary`, ordered `achievements` (lead phrase in `<b>…</b>`), optional per-role bullet overrides (`roles`), and optional `skills` groups. Companies, titles, dates, and education always come from `profile.ts` and the messages, so facts stay consistent.
- **Contact:** `RESUME_EMAIL` and `RESUME_PHONE` in `.env.local` are rendered only on variant resumes.
- **Rendering:** `/[locale]/resume/pdf?variant=<id>`. `loadResumeVariant` validates the id (`[a-z0-9-]` only) and returns nothing when `NODE_ENV === "production"`, so the route 404s for variants in production. The `private/` folder is also never deployed.
- **Output:** `npm run resume:pdf` writes each variant to `private/resumes/<fileName>`, verifies one page, and fails if email/phone links ever appear in a public PDF.

To add a variant, copy an existing JSON, change `id`/`fileName`/content, and rerun `npm run resume:pdf`. Back up `private/` separately, because it is not in git.

## Content Model

Content is split between structure and text:

- **`src/lib/profile.ts`** holds non-translatable structure: company names, role ids, start/end dates (`YYYY-MM`, `null` = current), employment type, impact metric ids and kinds (`change` or `value`), education, and links.
- **`messages/{locale}.json`** holds all display text, keyed by those ids:
  - `Profile`: name, headline, location, summary, strongest fit, personal note, stats, impact, roles (title, location, summary, highlights), skills, education, employment types, and `onePage` (condensed summary, achievements, role bullets, and ATS section headings used only by the PDF).
  - `Site`: metadata, navigation, section labels, actions, footer, language notices.
  - `ResumePage`: resume-only labels.

To add a role: add it to the company's `roles` in `profile.ts`, then add `Profile.roles.<id>` in all three message files. To add an achievement: add it to `IMPACT` and add `Profile.impact.<id>` in all three message files. Dates are formatted per locale by `DateRange` (server) and in English by `llms.txt`.

All server components read text with `getTranslations`. Client components (`HeaderControls`, `PrintButton`, `LanguageSelector`) receive text as props, so `NextIntlClientProvider` is given `messages={null}` and no message catalog ships to the browser.

## AI and ATS Scannability

- Server-rendered semantic HTML: one `h1`, `h2` section labels, `h3` items, `dl` for metrics/skills, `<time datetime>` for dates.
- JSON-LD `ProfilePage` → `Person` with `jobTitle`, `worksFor`, `alumniOf`, `address`, `knowsAbout` (localized skills), `knowsLanguage`, and `sameAs` (LinkedIn, GitHub). No email is published.
- `/llms.txt` is a complete English profile: summary, contact, strongest fit, stats, impact with metrics, full experience with highlights, skills, and education.
- Per-locale metadata with canonical URLs, `hreflang` alternates (including `x-default`), and Open Graph `profile` type.
- The printed resume produces a text-extractable PDF.

## Design System

- **Layout**: single centered column (`max-w-3xl`), generous vertical rhythm (80px between sections).
- **Typography**: Inter; small uppercase, letter-spaced section labels; body text at 1.7 line height.
- **Color**: Mantine theming only. One accent via `--site-accent` (`blue-7` light, `blue-4` dark) for WCAG AA contrast; secondary text uses `c="dimmed"`.
- **Theme**: light/dark via Mantine `ColorSchemeScript` (no flash) and a header toggle.
- **Motion**: none beyond Mantine defaults; `prefers-reduced-motion` respected.
- **Note**: Mantine component styles override Tailwind margin/display utilities. Use Mantine style props (`mt`, `mb`, …) on Mantine components, and wrap them in a plain element when Tailwind `print:hidden` is needed.

## Accessibility

- Skip link, labeled primary navigation, `aria-current` on the active page.
- Before → after metrics (`kind: "change"`) include screen-reader text ("from {before} to {after}"). Public impact metrics currently use qualitative `value` metrics so internal Microsoft numbers stay off the public site; exact figures live only in the private resumes.
- Theme toggle and icon-only controls have accessible labels; decorative icons are `aria-hidden`.

## Internationalization

- Locales: `en`, `fr`, `de`; every key exists in all three files.
- French uses the formal register and shows a notice that conversations will be in English.
- German keeps common English job titles and shows a notice of C1 reading / B2 speaking.
